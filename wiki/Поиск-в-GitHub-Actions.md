# Поиск в GitHub Actions

Прежний вариант Customers: Python-конвейер, который ищет лиды по расписанию в GitHub Actions, хранит их в Notion
и присылает уведомления в Telegram. Он по-прежнему работает, но приложению для macOS больше не нужен: с версии 1.0.2
поиск идёт прямо в приложении.

> **Публичным должен быть код, а не собранная база.** Лиды и контакты хранятся в Notion и в зашифрованном кэше
> GitHub. В репозиторий и в логи Actions они не попадают.

## Как это работает

```
GitHub Actions (cron, раз в час)
  │  восстановить зашифрованное состояние из кэша → нет кэша? восстановить ключи из Notion
  ▼
Источники (каждый со своим интервалом, лимитами, курсором и журналом ошибок)
  FL.ru RSS · Telegram-каналы · VK-сообщества · OpenStreetMap + проверка сайтов
  ▼
Нормализация → Lead (единая модель) → собственный scoring → дедупликация (ID + отпечаток текста/домена)
  ▼
Маршрутизация во внешние адаптеры (необязательно): webhook (Make/n8n), Hunter
  ▼
Notion (upsert, с повторными попытками; недоступен → ждёт в локальной базе)
  ▼
Telegram (лиды, дайджест, ошибки одним сообщением, восстановление, сводка раз в сутки)
  ▼
зашифровать состояние → сохранить в кэш
```

Если отключить Notion, Telegram и все адаптеры, поиск, оценка и дедупликация продолжают работать. Результаты остаются
в зашифрованном состоянии и уходят в Notion, когда он снова доступен.

### Источники Python-версии

| Источник | Статус по умолчанию | Ограничения |
|---|---|---|
| FL.ru (`fl_ru`) | ✅ включён | RSS хранит только последние записи: если система стоит больше суток, часть заказов будет пропущена. Система предупреждает об этом |
| Telegram-каналы (`telegram_channels`) | ✅ включён, список каналов пуст | только публичные каналы с веб-превью `t.me/s/…`; после пропущенных запусков листает до 3 страниц назад |
| VK-сообщества (`vk_communities`) | ⏸ выключен | нужен бесплатный сервисный ключ, читаются только стены выбранных сообществ |
| OpenStreetMap (`osm_organizations`) | ✅ включён | полнота OSM в РФ ниже, чем у Яндекса и 2ГИС |
| Проверка сайтов | ✅ | только главная страница, не чаще раза в 60 дней |

Подробнее об источниках: [Источники](Источники).

## Установка шаг за шагом

### 1. Свой репозиторий

1. Сделайте форк этого репозитория (**Fork**): Actions в публичных репозиториях бесплатны.
   Перед этим прочитайте [LICENSE](https://github.com/xop1tt/Customers-App/blob/main/LICENSE): можно использовать и
   изменять для любых целей, кроме конкурирующего коммерческого продукта или сервиса.
2. Проверьте вкладку **Actions**: workflow **Tests** должен стать зелёным.

### 2. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя и сохраните токен.
   Это значение для `TELEGRAM_BOT_TOKEN`.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`.
   Это значение для `TELEGRAM_CHAT_ID`. Для группы добавьте бота в группу, и id будет отрицательным.

### 3. Notion

1. Откройте [notion.so/profile/integrations](https://www.notion.so/profile/integrations), нажмите **New integration**
   (тип Internal) и скопируйте токен в секрет `NOTION_TOKEN`.
2. Создайте базу с нужными полями: вручную (список полей и их типов — в `SCHEMA` в
   [`src/leadgen/storage/notion.py`](https://github.com/xop1tt/Customers-App/blob/main/src/leadgen/storage/notion.py), названия должны совпадать точно)
   или командой. Для команды нужен Python 3.11 или новее (`python3 --version`). Сначала создайте пустую страницу,
   например «Лиды», и через **⋯ → Connections** подключите к ней интеграцию: база создаётся внутри этой страницы.
   ```bash
   pip3 install -r requirements.txt
   NOTION_TOKEN=токен PYTHONPATH=src python3 -m leadgen notion-init --parent ID_СТРАНИЦЫ
   ```
   `ID_СТРАНИЦЫ` — 32 символа в конце адреса страницы. Команда создаёт базу и печатает её ID.
   Угловые скобки в zsh/bash писать нельзя.
3. Откройте базу, нажмите **⋯ → Connections** и подключите интеграцию. Без этого API ответит 404.
4. ID базы (32 символа в её адресе) положите в секрет `NOTION_DATABASE_ID`. Это не секретное значение.

### 4. Ключ шифрования состояния

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните результат в `STATE_ENCRYPTION_KEY`. Если ключ потерять или сменить, система восстановится из Notion
(за последние `storage.restore_days` дней).

### 5. GitHub Secrets и переменные

Откройте **Settings → Secrets and variables → Actions**.

| Тип | Имя | Обязательно |
|---|---|---|
| Secret | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NOTION_TOKEN`, `NOTION_DATABASE_ID`, `STATE_ENCRYPTION_KEY` | да |
| Secret | `VK_SERVICE_TOKEN`, `HUNTER_API_KEY`, `WEBHOOK_URL`, `WEBHOOK_SECRET` | нет |
| Variable | `LEADGEN_MODE` | нет: пока не задана, система работает в режиме `dry-run` и ничего не отправляет |

### 6. Настроить источники

Скопируйте [`config.example.yaml`](https://github.com/xop1tt/Customers-App/blob/main/config.example.yaml) в `config.yaml`, отредактируйте и закоммитьте.
Файл публичный, поэтому личных данных и секретов в нём быть не должно.

- `telegram_channels.channels` — имена публичных каналов с заказами. Проверьте, что `https://t.me/s/<имя>` открывается.
- `osm_organizations.regions` — ваш город, например `{name: Казань}`.
- Для VK создайте приложение на [dev.vk.com](https://dev.vk.com), возьмите **сервисный ключ доступа**, положите его
  в `VK_SERVICE_TOKEN`, заполните `communities` и поставьте `enabled: true`.

**Ещё одна RSS-лента** — без кода, достаточно добавить блок:

```yaml
  my_feed:
    type: rss
    enabled: true
    interval_hours: 2
    feeds: [{url: https://example.ru/rss}]
```

Фильтры и веса оценки: [Оценка и фильтры](Оценка-и-фильтры#настройка-весов).

### 7. Первая проверка (без реальных уведомлений)

1. Запустите **Actions → Diagnose → Run workflow**. В выводе будет видно, какие секреты заданы и какие источники готовы.
2. Запустите **Actions → Lead search → Run workflow** с `force: true`. Режим по-прежнему dry-run: в Summary запуска
   будет видно, сколько найдено и какие источники упали. Содержимое лидов в публичный лог не пишется.
3. Если источник падает (например, FL.ru блокирует зарубежные IP), об этом будет сказано в Summary.

> Парсеры проверены на тестовых данных по документированным форматам: из среды разработки внешние сайты были
> недоступны. Первую живую проверку нужно сделать самостоятельно.

### 8. Боевой режим (только после вашего решения)

1. Задайте переменную `LEADGEN_MODE` = `live`.
2. Запустите **Diagnose** с `ping: true`: в Telegram должно прийти тестовое сообщение, в выводе — `Notion: {'ok': True}`.
3. Дальше всё работает по расписанию.

Уведомления о лидах, найденных в режиме dry-run, при переходе в live повторно не приходят.

## Расписание

> С версии 1.0.2 расписание в `search.yml` выключено: поиск идёт в приложении. Запустить поиск в Actions можно
> вручную (**Actions → Lead search → Run workflow**). Чтобы вернуть ежечасный запуск, раскомментируйте блок `schedule`
> в начале [`search.yml`](https://github.com/xop1tt/Customers-App/blob/main/.github/workflows/search.yml).

Когда расписание включено, workflow запускается каждый час, а каждый источник сам решает, пора ли ему работать
(`interval_hours`):

| Источник | По умолчанию |
|---|---|
| FL.ru | 2 ч |
| Telegram-каналы | 3 ч |
| VK | 3 ч |
| OpenStreetMap | 120 ч (5 дней), один и тот же запрос не чаще 7 дней |

- Расписание GitHub может задерживаться. Интервалы считаются с допуском 10 минут.
- После сбоя источник пробуют снова на следующем часовом запуске.
- Пропущенные запуски: RSS и каналы догоняют с последней обработанной записи в пределах истории источника
  (у RSS это последние записи ленты, у каналов `max_pages_per_channel` страниц). Если догнать не удалось, в Summary
  появится предупреждение.
- Параллельные запуски исключены: `concurrency: lead-search`.
- **60 дней без активности.** GitHub отключает расписание публичного репозитория, если в нём 60 дней не было коммитов.
  На 50-й день бот предупредит в Telegram. Искусственных коммитов система не делает: сделайте осмысленный коммит
  (например, обновите настройки) или после отключения нажмите **Enable workflow** во вкладке Actions.

## Команды CLI

```bash
PYTHONPATH=src python3 -m leadgen run [--sources fl_ru] [--force]   # поиск, dry-run по умолчанию
PYTHONPATH=src python3 -m leadgen diagnose                          # секреты, источники, состояние
PYTHONPATH=src python3 -m leadgen state pack|unpack --enc FILE      # шифрование состояния для кэша
PYTHONPATH=src python3 -m leadgen export --format json|csv --out FILE
PYTHONPATH=src python3 -m leadgen notion-init --parent ID_СТРАНИЦЫ
```

Для локальной отладки с выводом текстов заявок: `LEADGEN_SHOW_MESSAGES=1`.

## Будущие команды бота

`/status`, `/stats`, `/pause`… Данные для них уже есть в `source_state`, `request_stats` и `errors`, а
`python -m leadgen diagnose` выводит то же самое. Команды можно реализовать отдельным workflow, который раз в N минут
читает `getUpdates`. В первую версию они не вошли.
