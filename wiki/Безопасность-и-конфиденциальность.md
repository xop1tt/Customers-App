# Безопасность и конфиденциальность

Сообщить об уязвимости: **Security → Report a vulnerability** в репозитории, не публичным issue.
Подробнее: [SECURITY.md](https://github.com/xop1tt/Customers-App/blob/main/SECURITY.md).

## Приложение для macOS

- Приложение обращается только к самим источникам (FL.ru и ваши RSS-ленты, t.me, api.vk.com, overpass-api.de),
  к сайтам найденных организаций (один запрос на главную страницу) и с выбранной частотой (по умолчанию раз в сутки) к публичному API GitHub для проверки
  обновлений (отключается).
- Никаких своих серверов и аналитики: у локальной учётной записи лиды не покидают Mac.
- Облачная учётная запись дополнительно хранит данные в **вашем** проекте Supabase. Доступ к строкам — только у владельца
  (Row Level Security). В приложении хранятся только адрес проекта и публичный ключ; с секретным ключом приложение
  работать откажется.
- Локальная база лидов (`leads.db`) и её резервные копии зашифрованы SQLCipher (AES-256). Ключ — 32 случайных
  байта, создаётся при первом запуске и хранится в Связке ключей (запись «Customers: ключ шифрования базы лидов»).
  Базы прежних версий переписываются в зашифрованные при первом открытии: данные сверяются по числу записей до
  удаления исходного файла, прерванная замена доводится до конца или откатывается при следующем запуске.
  Без ключа ни база, ни копии не открываются, в том числе на другом Mac (см. [Резервные копии](Резервные-копии-и-экспорт)).
  Файл учётных записей (`accounts.db`) содержит только имена, соль и хэши паролей и не шифруется.
- Ключ VK, запомненный вход и токены облака лежат в Связке ключей. Доступ к ним разрешён только приложению
  с той же подписью: поэтому после смены подписи macOS спрашивает пароль. Подтверждение через Touch ID для этих
  записей требует платного Apple Developer ID (защищённая связка ключей доступна только приложениям с ним), поэтому
  его нет. Пароли локальных учётных записей — только в виде
  соли и хэша PBKDF2-SHA256 (310 000 итераций).
- Отчёты о сбоях сами никуда не уходят: вы видите и правите текст, домашняя папка и имя пользователя скрыты.
- Обновления: dmg сверяется по SHA-256 из того же релиза. Это защита от повреждённой загрузки, а не подпись Apple:
  сборка подписана ad-hoc.

## Приложение для Windows

- Сетевая картина та же, что на macOS: только источники, сайты найденных организаций, проверка обновлений на GitHub (отключается) и ваш проект Supabase при облачной записи.
- База лидов зашифрована SQLCipher, ключ защищён DPAPI (привязан к вашей учётной записи Windows). Токены, пароль почты, ключи и вебхуки лежат в `%LOCALAPPDATA%\Customers\secrets` в виде DPAPI-файлов, отдельно для каждой записи.
- Облако общее с macOS: те же таблицы и политики Row Level Security, структура Supabase для Windows не менялась.
- Установщик сверяется по SHA-256 из того же релиза; подписи Microsoft у него нет. Подробности: [desktop/README.md](https://github.com/xop1tt/Customers-App/blob/main/desktop/README.md).


## Репозиторий и CI

- Ветка `main` защищена: слияние только через PR после зелёных проверок.
- CodeQL, dependency review, Dependabot, secret scanning и push protection.
- Права workflow минимальные (`contents: read`, запись только у выпуска релиза). Сторонние Actions закреплены по полным
  SHA, Dependabot предлагает обновления.
- `tests.yml` не получает секретов, `pull_request_target` не используется. Ввод `workflow_dispatch` передаётся в shell
  через переменные окружения и проверяется регуляркой.

## Правила сбора данных

- CAPTCHA, авторизация и запреты `robots.txt` не обходятся. Источники с запретами не подключены.
- Сохраняются только контакты, которые человек или организация сами опубликовали. Используйте их в рамках 152-ФЗ
  и правил площадок.
- Для холодных рассылок по найденным контактам законодательство РФ требует осторожности: это решение владельца,
  а не системы. Приложение не делает массовых рассылок: черновик обращения отправляется только вручную.
