# Тестирование

## Что запускается автоматически

| Проверка | Где | Что проверяет |
|---|---|---|
| `Customers.Core.Tests` (246) | Windows и Linux | оценка, дедупликация, поиск и разбор источников, база и шифрование, резервные копии, учётные записи, облачная синхронизация, экспорт и импорт, CRM, обновления, OAuth (PKCE, обновление токена, сервер возврата на сокете), WebDAV и загрузка на диски, SMTP и MIME |
| `Customers.Presentation.Tests` (55) | Windows и Linux | модели представления: фильтры, выбор, поиск в фоне и отмена, резервные копии и восстановление, вход и выход, облако, восстановление повреждённой базы |
| Сборка с `TreatWarningsAsErrors` | Windows и Linux | любые предупреждения компилятора и анализаторов — ошибка |
| `dotnet format whitespace --verify-no-changes` | Linux | единое форматирование всех проектов, включая интерфейс |
| Сборка WinUI и публикация (self-contained) | Windows | XAML компилируется, пакеты разрешаются, приложение собирается |
| `Customers.exe --smoke` | Windows | реальный запуск окна: регистрация, наполнение базы, переход по всем разделам и страницам настроек, смена темы и материала, экспорт/импорт, копия/восстановление, исключения, смена пароля и повторный вход, живая смена акцентного цвета (цвет кнопки в светлой и тёмной теме), WebDAV-выгрузка копии на локальный сервер, возврат OAuth через `localhost`, настройки почты и пароль в DPAPI, скрытие окна и возврат, меню значка, автозапуск в реестре, скриншоты |
| Установщик | Windows | сборка Inno Setup, установка без прав администратора, запуск установленного приложения, установка поверх с сохранением данных, регистрация ссылок и записи в «Приложениях», удаление |
| Pytest `tests/test_workflows.py` | Linux | правила безопасности workflow репозитория (включая новые Windows-файлы) |

Артефакты проверок (результаты, скриншоты, журнал установки) прикрепляются к запуску в Actions.

## Локально

```powershell
cd windows
dotnet test tests/Customers.Core.Tests
dotnet test tests/Customers.Presentation.Tests
./tools/smoke.ps1 -Exe artifacts/publish/Customers.exe -Output artifacts/smoke   # после publish, см. build.md
```

## Чего автоматические проверки не покрывают

* **Внешний вид и удобство.** Smoke-тест делает скриншоты и убеждается, что страницы создаются без исключений, но не оценивает вёрстку. Проверка «глазами» на Windows 10 и Windows 11 (в том числе с разными масштабами экрана) остаётся ручной.
* **Живые источники.** Тесты используют записанные ответы; реальные RSS, Telegram, VK, Overpass и Supabase в CI не вызываются.
* **Тест хранилища DPAPI** выполняется только на Windows (на Linux хранилище заменено тестовым).
* **Реальные сервисы.** Вход в Google, Dropbox, Microsoft и отправка через почтовые серверы в CI не вызываются.
* **Системные уведомления** (тосты) зависят от параметров Windows и в CI не проверяются.
* **Обновление из приложения** проверено на уровне загрузки и сверки SHA-256, но не полным циклом «релиз → приложение → установка».

## Правила

Тесты не отключаются ради зелёной сборки; тест, падающий только на одной ОС, считается найденной ошибкой (так были найдены блокировки файлов SQLite на Windows).
