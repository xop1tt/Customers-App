# Календарь CRM (пакет G2)

Решение — ADR-055. Только приложение: новых столбцов, команд ядра и миграций нет.

## Что показывает

* Раздел **CRM → Календарь** (`SectionId` `calendar`, `app/crm/CalendarPage.tsx`).
* **Месяц** (целые недели с понедельника) и **неделя** (7 столбцов со всеми записями дня).
* **Задачи** — по сроку `due_at`; выполненные и отменённые зачёркнуты, просроченные — красной полосой.
* **События** (звонки, письма, встречи и др. из `activities`) — по времени `occurred_at`, фиолетовой полосой.
  Служебные события (`type = system`) не показываются.
* **Мои / Все**: «Мои» — задачи участника и задачи без исполнителя (как на экране «Сегодня»), события, которые
  записал он сам. «Все» — всё, что видно по правам роли.
* В месяце в ячейке до 3 записей, остальные — «ещё N»; щелчок открывает эту неделю.

## Действия

| Действие | Как | Права |
|---|---|---|
| Открыть задачу | щелчок по записи | просмотр |
| Открыть клиента события | щелчок по событию (открывается запись, к которой оно привязано) | просмотр |
| Перенести срок | перетащить задачу на другой день или меню «Перенести на сегодня / завтра / следующую неделю» | `can(perms, "edit", task, me)`: `records.edit` или `records.edit_own` для своей задачи |
| Новая задача на день | «+» в ячейке дня или кнопка «Задача» | `records.create` |

* При переносе сохраняется время задачи (часы и минуты по местному времени), меняется только день.
  Сохранение — обычный `ws_save("tasks", id, {due_at})`, поэтому работают очередь синхронизации, конфликты и
  история изменений.
* Новая задача открывается в карточке с заполненным сроком 10:00 выбранного дня: `openRecord(table, "new", preset)`,
  `preset` подмешивается к значениям по умолчанию (`NewRecord` в `CrmCard.tsx`).

## Устройство

* `lib/calendar.ts` — чистая логика: сетка (`visibleDays`, `weekStart`, `shift`), подписи (`periodTitle`, `dayTitle`,
  `weekdays`), записи (`calendarItems`, `byDay`), перенос (`moveToDay`, `defaultDue`), границы запроса (`queryRange`).
* Данные: два запроса `ws_list` (задачи по `due_at`, события по `occurred_at`) с фильтрами `gte`/`lt` на видимый
  период плюс сутки с каждой стороны (значения хранятся в UTC, дни — местные).
* Вид — токены `styles/tokens.css`, классы `.cal-*` в `styles/app.css`; при ширине области меньше 760 px в месяце
  скрывается время.

## Попутное исправление ядра

Встроенная функция SQLite `lower()` переводит в нижний регистр только латиницу, поэтому поиск «ромашка» не
находил «Ромашка». `WorkspaceStore::open` подменяет `lower()` версией с Юникодом (`unicode_lower` в
`workspace/store.rs`, функция rusqlite `functions`). Это касается поиска, фильтра «содержит» и сопоставления этапов
при импорте. Тест: `workspace::tests::search_ignores_case_of_russian_letters`.
