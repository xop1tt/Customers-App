# Debug Menu (только Beta)

Статус: **реализовано** (этап 2), кроме отмеченного «позже». Проверено тестами ядра и интерфейса в контейнере
(Linux); окна macOS и Windows проверяются сборками `desktop.yml` и `beta.yml`.

## 1. Где живёт и почему его нет в Stable

* Rust: `desktop/src-tauri/src/debug/` подключается строкой `#[cfg(feature = "beta")] pub mod debug;` в `lib.rs`.
  Команды (`debug_*`) — в отдельном обработчике `debug_handler()`, который тоже существует только при `beta`;
  общий обработчик отправляет в него вызовы с префиксом `debug_`. В Stable нет ни кода, ни команд: вызов из
  интерфейса получил бы «команда не найдена».
* Единственная новая зависимость — `sysinfo` (память и процессор процесса, версия ОС) — объявлена
  `optional = true` и включается только признаком `beta = ["dep:sysinfo"]`.
* `release-check.cjs` отклоняет сборку, если модуль подключён без `cfg(feature = "beta")`, если признак `beta`
  включает что-то кроме необязательных зависимостей или если такая зависимость не помечена `optional`
  (`tests/test_channels.py` проверяет, что каждое из этих нарушений ловится).
* Интерфейс: `desktop/src/debug/` — отдельный модуль, загружается `import()` только при открытии. Открыть можно
  пунктом «Debug Menu» в меню учётной записи и `Ctrl/Cmd+Shift+D` — то и другое только при `boot.channel === "beta"`.
  Файл модуля есть и в сборке Stable (интерфейс общий), но он не загружается, а его команды ядру Stable неизвестны.

## 3. Scenario Runner

* Реестр — таблица `SCENARIOS` в `debug/scenarios.rs`: `id`, группа, название, описание, функция
  `fn(&mut Ctx) -> Result<(), String>`.
* `Ctx` для каждого сценария создаёт **отдельную временную папку** `<данные Beta>/scenarios/<run-id>/<сценарий>`,
  своё окружение (`Env`) с секретами в памяти, без сети (любой запрос — ошибка «сценарии работают без сети»), без
  облака, и своё ядро `Core`. `Ctx::restart()` имитирует перезапуск приложения (новое ядро на тех же папках и
  секретах). После сценария папка удаляется; рабочие данные Beta не затрагиваются.
* Изоляция сценария: свои папки — папки сценария, папки другого канала — настоящие папки Stable этой системы
  (сценарий `isolation.other_channel` проверяет, что туда ничего не попадает).
* Каждый сценарий проверяет состояние: строки в снимке, отметки, файлы экспорта и копий, шифрование, события
  интерфейса. Ошибка или сбой (panic) — FAIL с текстом. SKIPPED не считается успехом в итоге.
* Сценарии (13): первый запуск и создание базы; вход и выход; восстановление сессии; смена пароля; создание,
  правка и удаление лида; избранное, архив, просмотр; исключения (в т. ч. импорт CSV); экспорт JSON и CSV;
  резервная копия и восстановление; сохранность данных после перезапуска; настройки после перезапуска; события для
  интерфейса; изоляция от другого канала.
* Без окна: `npm run debug:scenario` (`cargo test --features beta --test scenarios`) — тот же код на временной
  папке; идёт в CI вместе с `cargo test --features beta`.

## 4. Тестовые данные и защита

* Работают только в **локальной** учётной записи Beta, которую пользователь пометил тестовой (отметка хранится в
  её базе). В учётной записи с облаком или с включённой синхронизацией — отказ: данные ушли бы в Supabase.
  Перед записью проверяется, что база лежит в папке своего канала.
* Генератор детерминированный (SplitMix64): одинаковый `seed` и номер — одинаковые лиды (кроме даты обнаружения,
  которая отсчитывается от текущего момента). Повторная генерация продолжает нумерацию. Лиды пишутся одной
  транзакцией: тест на 10 000 лидов вместе с чтением снимка идёт около 3,5 с в отладочной сборке.
* «Удалить тестовые» удаляет только лиды с источником `test-data` и их историю.
* «Сбросить» удаляет все лиды, историю, исключения и журнал поиска этой учётной записи (настройки и отметка
  остаются) и только после ввода слова «сброс».

## 5. Журнал событий

* Кольцевой буфер на 5 000 записей и файл `<журналы Beta>/events.jsonl` (при 4 МБ становится `events.1.jsonl`);
  после перезапуска последние записи снова видны.
* Источники: запуск приложения, ошибки ядра (`Env::log_error`), события для интерфейса (имя и краткая суть —
  поиск, синхронизация, уведомления), действия Debug Menu, сценарии, записи интерфейса (`debug_log`).
* До записи маскируются: JWT и токены, ключи Supabase (`sb_…`), `Bearer …`, значения `password`, `token`,
  `secret`, `apikey`, `code` и т. п., адреса почты (`a•••@домен`), телефоны (`•••89`), домашняя папка и имя
  пользователя.

## 6. Диагностика и отчёт ZIP

Проверки: разделение каналов; папки данных, журналов и копий (запись пробного файла); целостность базы
(`PRAGMA quick_check`), версия схемы, шифрование, расположение базы; настройки устройства; файл приложения;
доступность Supabase (`/auth/v1/health` проекта Beta) или SKIPPED, если облако не настроено; синхронизация;
обновления; отчёты о сбоях Beta. Без входа проверки базы — SKIPPED с причиной.

`diagnostics-<дата>.zip` (ZIP без сжатия, открывается системными средствами): `report.json` (проверки),
`system.json` (Dashboard), `events.jsonl` (последние 2 000 записей), `isolation.json`, `crashes/*` (до 10 отчётов
Beta). Базы, ключи, токены и пароли не включаются; весь текст проходит маскирование. Сохранить отчёт в папку
другого канала нельзя.
