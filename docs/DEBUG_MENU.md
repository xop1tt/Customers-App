# Debug Menu (только Beta)

Статус: **запланировано** (этап 2). Здесь — устройство, которое будет реализовано; ничего из этого ещё нет в коде.

## 1. Где живёт

* Rust: модуль `desktop/src-tauri/src/debug/`, подключается строкой `#[cfg(feature = "beta")] pub mod debug;`
  в `lib.rs`; команды регистрируются в отдельном `generate_handler!` только при `beta`. В Stable кода нет вообще —
  `release-check.cjs` отклонит сборку, если модуль подключён иначе.
* Интерфейс: `desktop/src/debug/` загружается динамическим `import()` только при `boot.channel === "beta"`;
  в Stable вызовы debug-команд вернули бы «unknown command», потому что команд нет.
* Открытие: пункт «Debug Menu» в меню учётной записи и `Ctrl/Cmd+Shift+D` — только в Beta.

## 3. Scenario Runner

```rust
pub trait Scenario: Send + Sync {
    fn id(&self) -> &'static str;               // "leads.favorite"
    fn title(&self) -> &'static str;
    fn description(&self) -> &'static str;
    fn requires(&self) -> &[Requirement] { &[] } // Cloud, Network, Workspace — иначе SKIPPED с причиной
    async fn run(&self, ctx: &mut ScenarioCtx) -> Result<(), Failure>;
}
inventory::collect!(&'static dyn Scenario);   // или явный реестр в debug/scenarios/mod.rs
```

* `ScenarioCtx` создаёт **отдельную временную учётную запись** в папке Beta (`scenarios/<run-id>`), свой `Core`,
  и удаляет её после прогона. Рабочие данные Beta сценарии не трогают.
* Каждый сценарий проверяет **состояние данных** (строки в базе, снимок `snapshot()`, файлы), а не только
  отсутствие ошибки. Результат: `{id, status, duration_ms, error, details}`; SKIPPED всегда с причиной и не
  считается успехом в сводке.
* Первые сценарии (этап 2) — генератор лидов: первый запуск, инициализация базы, создание/правка/удаление лида,
  статусы, избранное, архив, исключения, поиск, фильтры, сортировка, источники, импорт CSV/JSON, экспорт,
  вход/выход/восстановление сессии, настройки и их сохранение после перезапуска (новый `Core` на той же папке),
  уведомления (записанные события), сохранность данных после перезапуска. Сценарии CRM добавляются вместе с
  функциями (этапы 3–7).
* Те же сценарии запускаются без окна: `npm run debug:scenario` → `cargo test --features beta --test scenarios`.

## 4. Тестовые данные и защита

* Генераторы работают только с учётной записью, помеченной `test_data = true`, в папке Beta. Перед любой
  операцией проверяется `Isolation::check_path` и метка канала; в Stable кода генераторов нет.
* «Сброс» удаляет только базу тестовой учётной записи и только после повторного подтверждения с вводом слова «сброс».
* Детерминированный генератор (seed) — одинаковые данные для воспроизведения ошибок.

## 5. Отчёт диагностики (ZIP)

`diagnostics-<дата>.zip`: `report.json` (все проверки), `system.json` (Dashboard), последние 2 000 событий,
отчёты о сбоях Beta, `isolation.json`. Не включаются базы, ключи, токены, пароли, почта и телефоны (маскируются).
