# Объединение дубликатов (пакет G4)

Решение — ADR-057. Схема, миграции и сервер не менялись.

## Как работает

* В карточке компании или контакта кнопка **«Объединить с дубликатом»** (иконка слияния). Видна, если роль может
  менять и удалять любые записи (`records.edit` и `records.delete`: владелец, администратор, менеджер).
* Шаг 1: выбор второй записи — «Похожие» (`ws_duplicates`: те же телефон, почта, домен, название) или поиск.
* Шаг 2: какая запись остаётся (по умолчанию та, из которой открыто окно) и таблица различающихся полей.
  По умолчанию: пустое поле берёт значение второй записи, телефоны и почта объединяются («Оба списка»),
  остальное остаётся как было. Логика — `desktop/src/lib/merge.ts`.
* **«Объединить»** вызывает `ws_merge` (`desktop/src-tauri/src/workspace/merge.rs`).

## Что делает ядро

| Шаг | Компании | Контакты |
|---|---|---|
| Значения полей | выбранные значения записываются в оставшуюся запись | то же |
| Прямые ссылки | `contacts.company_id`, `deals.company_id`, `crm_leads.converted_company_id` | `crm_leads.converted_contact_id` |
| Участие в сделках | — | `deal_contacts`: пара (сделка, контакт) уникальна, поэтому строка для оставшегося контакта создаётся (или восстанавливается), старая уходит в корзину; если контакт уже участвует в сделке, дубль связи не создаётся |
| Карточечные записи | задачи, события, заметки, комментарии, вложения: `entity_id` → оставшаяся запись | то же |
| Свои поля | значение оставшейся записи важнее; пустое заполняется значением второй | то же |
| Вторая запись | в корзину (`deleted_at`) | то же |
| Лента | событие `system` «Объединено с «…»» у оставшейся записи | то же |

Каждый шаг — обычный `save`: работают права, проверки, очередь синхронизации и разрешение конфликтов. Поля
`source`, `source_lead_id`, `source_payload`, `dedupe_keys`, `archived_at`, `deleted_at` выбрать нельзя. Ошибка
посреди объединения откатывает уже сделанные шаги.

Попутно: проверка ссылок в `WorkspaceStore::save` при переносе записи на другую карточку (`entity_id`) берёт тип
карточки из самой записи, если он не передан (раньше перенос без повторной передачи `entity_type` отклонялся).
Сервер проверяет то же самое в `crm_stamp` по новому значению строки.

## Отмена

* Снимок «как было» последнего объединения хранится в `local_meta` (`merge_undo`) вместе с `updated_at` и
  `version` каждой затронутой записи после объединения.
* В карточке оставшейся записи — заметка «Объединено с «…»» и кнопка **«Отменить»** (`ws_merge_last`,
  `ws_merge_undo`). Отмена возвращает значения в обратном порядке: сначала восстанавливается вторая запись, затем
  на неё снова ссылаются связанные.
* Отменить нельзя, если после объединения любая затронутая запись изменилась: правка или синхронизация с сервером
  (сервер повышает `version`). Это и есть «отмена до синхронизации» из дорожной карты. Позже вторую запись можно
  восстановить из корзины вручную, но связи придётся перенести самим.
