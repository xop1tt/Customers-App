# Отчёты по сделкам (этап 2, часть 1)

Раздел «Отчёты» — в модуле «CRM» рейки слева, под «Сегодня» и «Сделки». Только чтение: отчёты ничего не меняют
в данных. Считаются в интерфейсе (`desktop/src/lib/reports.ts`) из сделок (`ws_list`), этапов воронки и истории
этапов (`ws_stage_history`). Права те же, что у списка сделок.

## Настройки экрана

* Воронка — при нескольких воронках сверху выбор, по умолчанию `is_default`.
* Период — текущий месяц, квартал, год или всё время, по местному времени устройства.

## Показатели

| Блок | Как считается |
|---|---|
| Выиграно | сделки со статусом `won`, закрытые (`closed_at`) в периоде; сумма по валютам |
| Конверсия в успех | выигранные / (выигранные + проигранные), закрытые в периоде |
| Средний цикл сделки | среднее `closed_at − created_at` выигранных в периоде, в днях |
| Новых сделок | созданные (`created_at`) в периоде |
| В работе сейчас | открытые сделки на текущий момент и их сумма (не зависит от периода) |
| Воронка | сделки, **созданные** в периоде. Сделка «дошла» до этапа, если была на нём или на более позднем открытом этапе (по истории этапов и текущему этапу); выигранная прошла все открытые этапы. Справа — доля от предыдущего этапа |
| Причины проигрыша | `lost_reason` проигранных в периоде, без учёта регистра и пробелов по краям; пустая — «Причина не указана»; шесть самых частых |
| По ответственным | `owner_id`: открытые сейчас, выигранные в периоде, доля успеха; сначала больше выигравшие |

Удалённые сделки не учитываются нигде. Суммы в разных валютах не складываются и не пересчитываются.

## Прогноз и отчёты руководителя (пакет G3, ADR-056)

Тоже только интерфейс, без новых команд и столбцов. Экран дополнительно читает задачи и события (`ws_list`).

| Блок | Как считается (`lib/reports.ts`) |
|---|---|
| Прогноз на этот месяц | взвешенная сумма открытых сделок воронки с ожидаемой датой в текущем месяце (не раньше сегодняшнего дня) |
| Прогноз (`forecast`) | открытые сделки по `expected_close_date`: «дата прошла» (раньше сегодня), этот месяц, два следующих, «позже», «дата не указана». «Ожидается» = `amount × probability / 100`, вероятность — `pipeline_stages.probability` (ограничена 0–100). Сделки без суммы в деньгах не участвуют, их число показано под таблицей. Не зависит от периода |
| Динамика по месяцам (`monthly`) | последние 6 месяцев: создано по `created_at`, выиграно и проиграно по `closed_at`, сумма выигранных. Не зависит от периода |
| Источники клиентов (`sources`, `sourceName`) | новые компании периода по `companies.source` и выигранные в периоде сделки по источнику компании сделки. `import:…` → «Импорт из таблиц», `leadgen:x` → «Поиск клиентов · x», пусто → «Вручную»; сделка без компании → «Без клиента» |
| Сотрудники (`team`) | сделки как в `byOwner`; задачи, выполненные в периоде (`completed_at`), и открытые с прошедшим сроком — по `assignee_id`; события периода (кроме `system`) — по `created_by`. Строка «Не назначено» — задачи без исполнителя и сделки без ответственного |

## Ядро

`ws_stage_history` (Rust, `WorkspaceStore::stage_history_all`) возвращает историю этапов всех неудалённых сделок
Workspace: `deal_id`, `from_stage_id`, `to_stage_id`, `changed_at`. Схема и синхронизация не менялись.

## Не вошло (решение по ним — в треде этапа 2)

План/факт и правила «если → то» требуют новых общих данных (планы, правила, очередь событий), то есть изменений
схемы и синхронизации. Они ждут отдельного решения Maksim и PR с базой.

## Демо

`npm run dev`, адрес `?reports` (можно с `?team`): 18 демо-сделок за два месяца с историей этапов, причинами
проигрыша и разными ответственными.
