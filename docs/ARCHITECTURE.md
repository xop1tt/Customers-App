## 2. Слои

```
┌──────────────────────── desktop/src (React + TypeScript) ────────────────────────┐
│ app/ (экраны) · state/ (хранилище) · api/ (backend.ts → Tauri, mock.ts → демо)   │
│ lib/ (чистая логика интерфейса) · ui/ (кит)                                       │
└───────────────────────────────▲──────────────────────────────────────────────────┘
                                │ invoke / events (Tauri IPC)
┌───────────────────────────────┴───── desktop/src-tauri (Rust) ───────────────────┐
│ commands.rs (тонкие команды) → app/ (Core: сессии, данные, поиск, синхронизация) │
│ channel.rs (Stable/Beta) · paths.rs · secrets.rs (Keychain/DPAPI) · db.rs/store.rs│
│ search/ (генератор лидов) · cloud/ (Auth, sync) · crm/ (этап 3+) · debug/ (Beta) │
└───────────────┬───────────────────────────────────────────────┬──────────────────┘
                │ SQLCipher                                      │ HTTPS (anon/publishable key + JWT)
     локальные базы учётной записи                     Supabase: Auth · PostgREST + RPC · Realtime · Storage
     leads.db (генератор) · workspaces/<id>.db (CRM)   RLS на каждой таблице, функции в схеме private
```

Правила слоёв:

* Бизнес-правила CRM (кто что может, слияние полей, инварианты) живут **в PostgreSQL** (источник истины)
  и дублируются в Rust только как предварительная проверка для офлайн-режима. Расхождение решает сервер.
* Rust-ядро не знает об окне: всё, что связано с Tauri, — в `shell.rs`. Это позволяет тестировать `Core`
  без интерфейса (`app::testing::fixture`).
* Интерфейс не хранит бизнес-данные: только представление, полученное из ядра.

## 5. Ограничения среды

* Supabase Free: 500 МБ базы, 1 ГБ Storage, 2 млн сообщений Realtime и 200 одновременных подключений в
  месяц/проект, 50 000 активных пользователей Auth. Отсюда: пакетная выгрузка (до 500 изменений за запрос),
  Realtime только «звонком», вложения до 10 МБ, без опроса по таймеру.
* В облачном контейнере разработки нет Docker и доступа к `*.supabase.co`: стенд Supabase (`supabase/tests/stack`)
  и проверки macOS/Windows идут только в GitHub Actions. Такие проверки в отчётах помечаются «проверено в CI»
  или «не проверено», но не «пройдено» по предположению.
