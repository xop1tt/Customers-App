# Процесс разработки

## 1. Ветки

| Ветка | Что в ней | Как попадает |
|---|---|---|
| `main` | единственная постоянная ветка, из неё собираются релизы | только PR (из `feature/*` или `hotfix/*`) после зелёных обязательных проверок; без прямого push |
| `feature/<задача>` | крупная задача (например, `feature/workspaces`) | ветвится от `main`, PR в `main` |
| `hotfix/<задача>` | срочное исправление релиза | от `main`, PR в `main` |

Ветка `develop` закрыта 2026-11-10: всё из неё перенесено в `main`.

Защиту веток (Rulesets) настраивает владелец репозитория — см. RELEASE_PROCESS.md §3; автоматическое слияние
непроверенного кода в `main` запрещено.

## 2. Цикл

Канал один (ADR-034): Beta, Preview и ранний доступ не выпускаются, поэтому всё проверяется до слияния.

1. Изменение в `feature/*` → PR в `main` (CI: Desktop gate, Cloud gate, тесты, release-check; миграции — на стенде).
2. Слияние в `main` — Maksim после зелёного CI.
3. Тег `vX.Y.Z` → `release.yml` собирает приложение, проверяет установщики, ждёт подтверждения в окружении
   `production` и публикует релиз (RELEASE_PROCESS.md, RELEASE_CHECKLIST.md).

## 3. Версии

* SemVer `MAJOR.MINOR.PATCH` без суффиксов. Исторические четырёхчастные версии (1.0.6.2) по-прежнему принимаются.
* Источник версии — тег. `node desktop/scripts/set-version.cjs <версия>` пишет её в `package.json`,
  `tauri.conf.json`, `Cargo.toml`; `release-check.cjs --tag <тег>` проверяет, что всё совпадает.
  Файлы между релизами не обязаны совпадать с версией последнего релиза.

## 4. Команды (`cd desktop`)

| Команда | Что делает |
|---|---|
| `npm run dev` | интерфейс в браузере с демо-данными (флаги URL — CLAUDE.md §7) |
| `npm run tauri dev` | настоящее приложение из исходников — **с данными установленной версии** (папки, ключи, ссылки те же) |
| `npm run typecheck` / `npm test` | типы / тесты интерфейса (Vitest) |
| `npm run test:core` | тесты Rust-ядра |
| `npm run database:test` | тесты баз (`db::`, `store::`) |
| `npm run release:check` | готовность: версии, прежние идентификаторы, нет Beta, `debug` и devtools, нет ключей сервера |
| `npm run release:build` | сборка Customers |
| `npm run check` | всё быстрое подряд: типы, тесты интерфейса, ядро, release-check |

Из корня: `python -m pytest` — тесты Python, workflow и release-check (`tests/test_release_check.py`).
Новых команд-заглушек нет: команда появляется вместе с кодом, который она запускает.

Сборка из исходников работает как установленное приложение. Перед `npm run tauri dev` на рабочем компьютере
сделайте резервную копию или запускайте под отдельной учётной записью системы.
